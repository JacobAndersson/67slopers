# design-sync notes — hangboard

Repo-specific gotchas for future syncs. Read this before re-running.

## Shape

This repo is an **Expo app, not a published component library**. There is no
`dist/`, no build script, and `package.json` `main` is `expo-router/entry`. The
converter's package shape still applies, but only because we build a
web-renderable package ourselves first.

## The pre-build step (required before every sync)

`.design-sync/build/build.mjs` compiles `src/components/ui/*` into a small local
package at `.design-sync/build/pkg`, which is symlinked into `node_modules` as
`hangboard-ui`. It mirrors what `expo export --platform web` does:

- `react-native` resolves to `react-native-web`.
- JSX goes through NativeWind's runtime (`jsxImportSource: 'nativewind'`) so
  `className` works.
- `react` / `react-dom` are **shims onto `globalThis.React` / `globalThis.ReactDOM`**,
  not esbuild `external`s. NativeWind's CommonJS runtime calls `require("react")`
  at load time, which an external leaves unresolvable
  (`Dynamic require of "react" is not supported`).
- `@rn-primitives/slot` ships JSX inside a `.mjs`, so `loader: {'.mjs': 'jsx'}`
  is required.

Re-run order on any sync:

```sh
ln -sfn ../.ds-sync/node_modules .design-sync/node_modules   # once per clone
node .design-sync/build/build.mjs
cp .design-sync/build/dist/index.mjs .design-sync/build/pkg/dist/index.mjs
npx tsc -p .design-sync/build/tsconfig.dts.json               # .d.ts tree
npx tailwindcss -c .design-sync/build/tailwind.ds.js -i src/global.css \
  -o .design-sync/build/pkg/dist/styles.css
ln -sfn ../.design-sync/build/pkg node_modules/hangboard-ui   # once per clone
```

Then the normal driver run with
`--entry ./node_modules/hangboard-ui/dist/index.mjs`.

## The react-native-web / render-check interaction

react-native-web injects `<style id="react-native-stylesheet">` into `<head>`.
`package-validate.mjs` picks a preview's root with
`querySelectorAll('#root, [id^="r"]')` and takes the **first match in document
order**, which is that `<style>` — so every preview reported
`[RENDER] root empty` while rendering perfectly in a browser. The entry
(`.design-sync/build/entry.tsx`) renames the tag to
`ds-react-native-stylesheet` after mount. Do not remove that block; it is the
only reason the render check passes. If a future validate flags all components
empty at once, check this first.

## Stylesheet safelist

`.design-sync/build/tailwind.ds.js` adds a `safelist` to the app's own Tailwind
config. Without it the compiled CSS contains only the ~110 classes the app
literally uses, leaving the design agent with no layout vocabulary. With it,
448 classes ship at 36 KB. Same config and tokens; only tree-shaking differs.
If a class is documented in `conventions.md` but does not resolve, it is
missing from this safelist.

## Fonts

Geist Mono is registered one family per weight (see `src/lib/fonts.ts`), so the
web CSS references families like `GeistMono_600SemiBold`, not `font-weight`.
`.design-sync/fonts.css` declares the `@font-face` rules and the `.ttf` files
are committed under `assets/fonts/`. Without this the previews fall back to a
serif face.

## Known render warns

None. The final run was 8/8 clean: no `bad`, no `thin`, no
`variants render identically`.

## Metro and the sync tooling

`metro.config.js` block-lists `.ds-sync`, `.design-sync`, `ds-bundle`, `dist`, `competitors`
and the `node_modules/hangboard-ui` symlink. Without that, Metro's initial crawl (the
second node_modules tree plus the symlink cycle into `.design-sync/build`) stalled
indefinitely: `/status` answered but the manifest never did, and Expo Go reported
"Failed to download remote update". Keep the list in sync if the sync directories move.

## Re-sync risks

- **The pre-build is hand-rolled.** If `src/components/ui/` gains a component,
  add it to `.design-sync/build/entry.tsx` and to `pkg/dist/index.d.ts` or it
  will not appear in the design system.
- **`pkg/dist/index.d.ts` is written by hand.** The per-component `.d.ts` files
  under `pkg/dist/src/` are generated by `tsc`, but the barrel is manual and
  will drift as exports change.
- **The `node_modules/hangboard-ui` symlink is not committed** (gitignored) and
  must be recreated on a fresh clone.
- **Playwright pin**: the render check needs the playwright release matching the
  cached chromium build. This machine has `chromium-1148`, which is
  playwright 1.49.x; 1.50+ expects 1155 and fails with
  `Executable doesn't exist`.
- **Generated `.d.ts` is mostly React Native inherited props.** The real API is
  `variant` / `size` / `asChild` / `className`; `className` is absent from the
  types entirely. `conventions.md` documents this — keep that note if the types
  ever get regenerated differently.
